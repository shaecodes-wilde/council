# Decision-quality evaluation

These ten cases are an initial evaluation set, not recorded successful runs.
Expand toward 20 with real decisions from the user's work. Attach the same
frozen source bundle, user constraints and goal to each compared workflow:

1. One strong model.
2. Independent proposals plus synthesis.
3. Full Council including repair and verification.

Keep model versions/effort, source hashes and elapsed time. Record actual
provider usage/cost only where available; otherwise use unavailable or partial
totals. Do not estimate missing token usage as zero.

Present outputs to a human reviewer with the producing workflow hidden.
For each case record critical issues found/missed, unsupported consequential
claims, hard-constraint violations, whether the plan is executable without
earlier transcripts, and preference choices preserved. Use the case's checks
as observable criteria rather than requiring one canned design. Keep
mechanical regression tests separate from subjective plan usefulness.

Publish case-level results and limitations before claiming that additional
seats or rounds improve quality. Use that evidence before adding quick/deep
profile branches; the implemented default remains thorough.
